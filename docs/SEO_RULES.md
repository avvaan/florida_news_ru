# Как не выпасть из выдачи Google — правила для TutFlorida

Сайт молодой (домен с 23.11.2026), материалов мало, многое пишет ИИ. Для Google это зона риска: главное, что
может обрушить сайт, — **много малоценных страниц** (scaled content abuse, thin content). Наказание
обычно не «бан», а то, что Google перестаёт индексировать страницы и понижает весь домен. Ниже — что делать
и чего избегать. Правила относятся и к людям, и к ИИ-агентам, которые правят сайт.

## 1. Не плодить тонкие страницы

- **Не открывать для поиска страницы, где почти нет своего текста.** Карточка с названием, телефоном и
  одной-двумя фразами — тонкая. Её можно показывать людям, но закрывать `noindex` и не класть в sitemap.
- **Сначала проверка, потом индекс.** Данные, собранные автоматически (ИИ, поисковые выдержки, импорт), —
  только с `noindex`, пока человек не проверил. Пример: каталог «Детям» (`Club.is_indexable`).
- **Списки и подборки — только непустые.** Страница рубрики, города, тега, фильтра — в индекс, только если
  в ней ≥3 нормальных материалов. Пустые и почти пустые — `noindex, follow`.
- **Фильтры, сортировки, поиск, страницы 2+, формы, «спасибо» — всегда `noindex`.** Их бесконечно много.
- **Не создавать сотни страниц за раз.** Массовый импорт (кружки, бизнесы, врачи) — частями и с проверкой.
  Резкий скачок числа страниц на молодом сайте — сигнал для Google.

## 2. Тексты

- **Никакого «пересказа ради пересказа».** Заметка должна давать то, чего нет в источнике: что это значит для
  читателя, что делать, ссылки на гайды. Короткие пересказы (<150 слов) закрыты `noindex` автоматически,
  меньше «минимума слов» в настройках — уходят на проверку. **Минимум не снижать ради количества.**
- **Не выдумывать.** Ни цен, ни расписаний, ни отзывов, ни статусов. Неизвестно — «не указано».
- **Не копировать чужие тексты и фото.** Только свои формулировки и лицензированные или свои картинки.
- **Одинаковые шаблонные описания** на сотнях страниц («Отзывы русскоязычных клиентов…») — признак
  массового контента. Описание страницы должно быть про неё.
- **Украинская версия — только переведённая.** Страница `/uk/…` без перевода закрыта `noindex`
  (`shown_translated`). Не открывать `/uk/` с русским текстом.
- **Автор и проверка видны.** Подпись автора, дата, «проверено редакцией» — для доверия (E-E-A-T).

## 3. Техника

- **Один адрес — одна страница.** Канонический домен `tutflorida.com`, со старого `florida-ru.com`, `www` и
  `*.onrender.com` — 301. `canonical` указывает на саму страницу без параметров.
- **robots.txt не трогать без нужды.** Закрыты только `/admin/` и `/api/`. Никогда не ставить `Disallow: /`
  и не включать в Cloudflare блокировку ботов, которая задевает Googlebot.
- **sitemap — только то, что открыто для индекса.** Страница с `noindex` в sitemap — противоречие.
- **Сайт должен отвечать.** 5xx для Googlebot снижает частоту обхода. Выкладки на mimi перезапускают
  контейнер — **не выкладывать десятками подряд**, собирать правки в один релиз. Следить, чтобы сборка не
  падала (`collectstatic` в боевом режиме: `DJANGO_DEBUG=0 python manage.py collectstatic`).
- **Мета-тег Search Console** — только код, без `google-site-verification=` (срезается в `settings.py`).
- **Скорость.** Тяжёлые страницы (500+ КБ, например `/links/vrachi/`) — кандидаты на постраничный вывод.

## 4. Что проверять раз в неделю (Search Console)

- «Страницы» → **«Просканировано, но пока не проиндексировано»** и **«Обнаружено, не проиндексировано»**:
  если там растёт число карточек одного раздела — Google считает их малоценными: закрыть `noindex` или
  дописать.
- «Меры, принятые вручную» — должно быть пусто.
- «Статистика сканирования» — нет всплесков 5xx.
- Эффективность: какие страницы получают показы — их и развивать.

Главная рекомендация: **закрыть `noindex` и убрать из sitemap карточки справочника без отзывов и с
описанием короче ~80 слов**, оставив в индексе категории и страницы «категория + регион» — в них та же
информация собрана с пользой для читателя. Карточка открывается для поиска, когда у неё появляются отзывы
или нормальное описание.
