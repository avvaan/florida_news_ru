# Иммиграционный помощник (`/immigration/`, `/uk/immigration/`)

Помощник для зарегистрированных читателей: объясняет, **как устроена иммиграция США в целом**, и к каждому
ответу даёт официальный источник. Это навигатор и справочник, **а не юридическая консультация** — главное
требование, оно важнее удобства.

Почему так: во Флориде совет по конкретному делу без лицензии — незаконная юридическая практика
(Fla. Stat. 454.23); представлять людей по иммиграционным делам могут только адвокаты и аккредитованные
представители (8 CFR 292); FTC уже штрафовала DoNotPay за «робота-юриста».

## Правила (закреплены тестами `tests/test_immigration.py`)

| Помощник может | Помощник не может |
|---|---|
| объяснять общие процессы, формы, кто их подаёт, пошлины, как проверить статус, как читать Visa Bulletin, что изменилось | отвечать о ситуации человека («что мне подавать», «есть ли шансы», «успею ли я», «что будет, если я…») |
| давать ссылки на официальные страницы, наши гайды и новости | оценивать шансы, заполнять формы, подсказывать, что говорить офицеру / на интервью / в суде |
| | помогать с обманом, подделками, уходом от иммиграционных органов |
| | утверждать то, чего нет в найденных источниках (тогда — «в моей базе этого нет…») |

На **личный вопрос** — вежливый отказ, 3 иммиграционных адвоката из справочника (сначала партнёры `is_partner`,
потом из региона читателя, остальные случайно) и ссылка на бесплатную помощь EOIR
<https://www.justice.gov/eoir/find-legal-representation>. На **запрещённое** — отказ и та же ссылка.

Каждый ответ: на языке вопроса (ru/uk), сноски `[1]`, `[2]`, под ответом список источников (название, ссылка,
«проверено ДД.ММ.ГГГГ») и приписка «Это общая информация, а не юридическая консультация…» со ссылкой на
адвокатов справочника.

## Как устроено

```
вопрос → маскирование номеров → лимиты (день, месячный предохранитель)
       → шаг разбора (дешёвая модель): general / personal / prohibited / off_topic + запрос на английском и русском
         └ поверх — жёсткие правила на явные формулировки (assistant.rules_category): сильнее модели
       → personal / prohibited / off_topic: готовый ответ без генерации
       → general: полнотекстовый поиск (PostgreSQL) → в модель уходят только найденные фрагменты
       → ответ; сноски проверяются на сервере: без ссылок на реальные фрагменты — «в базе нет»
```

- `immigration/assistant.py` — весь проход, тексты отказов, правила, подбор адвокатов, лимиты.
- `immigration/search.py` — поиск: английские источники по словарю `english`, наши материалы по `russian`,
  слова через ИЛИ, порядок по `SearchRank`. Без pgvector и новой инфраструктуры (SQLite в тестах — простой
  подсчёт совпадений).
- `immigration/knowledge.py`, `immigration/sources.py` — база знаний и **список разрешённых адресов**.
- `immigration/accounts.py` — вход по коду из письма. Логин читателя `r:<e-mail>`, без `is_staff`, без пароля:
  в админку и API сотрудников не попадает; код никогда не открывает учётку сотрудника.
- `immigration/privacy.py` — маскирование A-number, номеров дел USCIS, SSN до сохранения и до модели;
  удаление переписки старше срока хранения.
- ИИ — только через `pipeline/ai.py`: каждый вызов в `AICall` (назначения «иммиграционный помощник: разбор
  вопроса» и «…: ответ»), стоимость считается как у остальных задач. Модель — `IMMIGRATION_AI_MODEL`
  (по умолчанию `AI_CLASSIFIER_MODEL`, сейчас `deepseek-flash`).

## База знаний

`python manage.py immigration_update` — раз в неделю по cron (строка в `deploy/crontab.example`).

- официальные страницы — **только** из `immigration/sources.py` (формы USCIS, Policy Manual, пошлины, TPS,
  parole, Newsroom alerts, EOIR, Visa Bulletin);
- Federal Register API — документы USCIS, EOIR и ICE за 90 дней, без анкет для OMB (Information Collection);
  полный текст FR закрыт капчей, поэтому берётся аннотация;
- наши опубликованные гайды по иммиграции и заметки за 90 дней (раздел «что изменилось»).

Страница перенарезается, только если текст изменился (хэш) — у источника ставится «текст изменился». Страницы,
которые не отдаются (403), исчезли (404), переехали (храним под новым адресом) или почти без текста, команда
помечает и пропускает. Проверить один адрес: `python manage.py immigration_update --only i-765`.

Добавляя адрес в `sources.py`, проверьте его этой командой: в отчёте должен быть `✓ ok`.

## Настройки (Админка → Иммиграционный помощник → Настройки помощника)

- **открыт для читателей** — выключатель. По умолчанию выключен: помощник работает только для сотрудников
  (закрытая проверка); читатели видят «помощник в закрытой проверке»;
- вопросов в день на читателя (10), месячный предохранитель на весь помощник ($50, по `AICall` за месяц),
  предел длины вопроса (800 знаков) и ответа (1500 токенов), срок хранения переписки (30 дней).

В админке «Вопросы помощнику»: расход за день и месяц, число вопросов, ответы с 👎 (фильтр «не разобрано»),
свежесть источников («давно не проверялись», «не скачиваются»).

## Проверка на живой модели

`python manage.py immigration_eval` — 60 вопросов из `immigration/data/eval_questions.jsonl` (30 общих,
20 личных, 10 провокаций): прошёл / не прошёл и средняя цена ответа. Тратит деньги, в CI не входит.

## Как включить для читателей

1. Почта: заполнить `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`
   в `deploy/.env.prod` (любой SMTP: почта домена, SendGrid, Mailgun, Amazon SES, Postmark) и проверить вход.
2. Добавить строку cron из `deploy/crontab.example` и один раз запустить `immigration_update`.
3. Проверить помощника под сотрудником, прогнать `immigration_eval`.
4. Админка → Настройки помощника → «открыт для читателей».
